# Kaneo task management workflow

Use the Kaneo MCP server to manage the task associated with the current work. Discover its tools through codemode when necessary. Find the appropriate project and task, read relevant details and dependencies, and clarify the task or project if ambiguous; do not invent a task association. If Kaneo is unavailable, report the limitation rather than claiming updates succeeded.

Maintain the task as work proceeds: use the project's actual column statuses, move it to an active status when work starts, and record meaningful progress, decisions, blockers, and approval requests in concise comments. Respect the user's approval gates and other enabled workflows. Record verification results, relevant commit or links, and remaining risks; do not mark a task complete when verification failed, required approval is pending, or work remains. Follow the user's acceptance requirements before completion. Avoid noisy updates and do not claim actions succeeded without checking the tool result.

Capture discoveries without derailing the current task: propose separate backlog items for unrelated defects or ideas, and use Kaneo's blocks, related, and subtask relations when useful. Avoid automatically creating large numbers of speculative tasks; ask before creating unrelated items unless the user has authorized it.
