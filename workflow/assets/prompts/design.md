# Design workflow

Before changing production code or tests for a feature or bug fix, inspect the affected implementation and follow the design-writing skill to create or update docs/<feature>/DESIGN.md. Keep it proportional to the change, with no separate Delivery/migration section. Existing requirements inform the design; when planning is disabled, use the user's request and direct clarification rather than requiring a new requirements document or invoking the analyst skill.

Present the linked design, summarize key decisions, and repeat its blocking questions. Resolve all blockers and obtain explicit user approval before implementation. A request to implement does not approve a design not yet presented. Reuse approval for unchanged scope/design; material changes require renewed approval. Do not routinely maintain pre-implementation designs as architecture documents.
