# Workflow Extension — Design

## Overview
The copy refinement removes the selector title's em dash, abbreviates the current user's home directory as `~` in selector and status paths, and labels the project action `Restore`. Status omits both `(enabled: <source>)` and `(from <source>)` annotations, the successful-discovery informational line, and the trailing prompt/context advisory. This is a presentation-only change; native selection, draft state, provenance data, and persistence remain unchanged.

A small `workflow/` extension offers a native selection popup for four configurable instruction bundles: short workflow prompts plus optional native Pi skills. Prompts refresh before each agent run; skill discovery happens only at startup and `/reload`. All steps default on, and project overrides belong to the session working directory, as agreed in the [requirements](REQUIREMENTS.md).

## Components
| Package/module | Component | Change | Responsibility |
|---|---|---|---|
| `workflow/index.ts` | Native extension entry | New, proposed | Register `/workflow`, `resources_discover`, and `before_agent_start`; wire adapters |
| `workflow/domain/` | Configuration resolver and composer | New, proposed | Validate values, merge fields with provenance, parse commands, order prompt contributions; pure logic |
| `workflow/app/` | [Workflow controller](../../workflow/app/controller.ts) | Changed | Coordinate reads/writes, own runtime discovery state, and render status with abbreviated paths and no source annotations |
| `workflow/app/` | Path display helper (proposed) | New | Share home-directory abbreviation between selector and status without changing stored paths |
| `workflow/infra/` | Filesystem and Pi adapters | New, proposed | Resolve paths, read prompts/configuration, write safely, publish command output and native resources |
| `workflow/ui/containers/` | [Selection dialog](../../workflow/ui/containers/selection.ts) | Changed | Format the scope/path title, bind a command-local draft to native `ctx.ui.select`, and return Save or cancellation |
| Configuration files | Shipped `workflow/workflow.default.json`, global/project `workflow.json`, prompts, skills | Changed, proposed | JSON owns default enabled states and resource associations; personal overrides remain user-owned |
| Pi | Native resource loader and structured prompt builder | Reused | Advertise skills, expand `/skill:name`, load skill bodies on demand, track prompt changes |
| Existing personal guidance | Mock/analyst/design skills, developer gates, memory preferences | Changed only after separate migration approval | Remove duplicate mandates while retaining non-workflow guidance |

No custom terminal widget, Middleware layer, filesystem watcher, or shared utility package is needed. Configuration is authoritative on disk; discovery bookkeeping lives for one runtime, and popup drafts live only until Save or Cancel. The controller owns draft transitions; the thin dialog binds values/actions to Pi's selector. Domain has no filesystem or SDK dependencies. Tests mirror these layers under `workflow/tests/`, with integration drivers in a separate `integration/support/` directory, following the existing [test runner](../../scripts/test.cjs).

## Runtime flow
1. At `resources_discover`, the controller reads shipped `workflow/workflow.default.json`, global configuration from `getAgentDir()`, and, only when `ctx.isProjectTrusted()` is true, `.pi/workflow.json` directly beneath `ctx.cwd`. The shipped file is located relative to the extension module, never the session cwd. No Git or ancestor lookup occurs.
2. The resolver merges shipped JSON defaults → global fields → explicit project fields. Global/project paths remain relative to their declaring configuration file; the shipped file is a global installation template, so its relative paths use `<agent-dir>` rather than the extension directory. The filesystem adapter validates enabled resources. The controller returns unique absolute `SKILL.md` paths through `skillPaths` and records the submitted selection. Pi performs native parsing, advertises descriptions, and retains its own diagnostics; submitted does not mean successfully loaded.
3. At `before_agent_start`, the controller rereads shipped defaults, configuration and enabled prompt files, composes them in mock → plan → design → commit order, and assigns only `event.systemPromptOptions.sections.workflow`. With no prompt contributions, it deletes that key. It does not replace the full system prompt or mutate Pi's skills list.
4. `/workflow` opens the project selector, initialized from effective settings. Its four rows use `[x]`/`[ ]` indicators in mock → plan → design → commit order, followed by Restore, Save, and Cancel. Selecting a step toggles its draft value and reopens the native dialog; Cancel/Escape discards the entire draft without writes. Restore stages removal of project `enabled` overrides and displays global/default values; it does not reset prompt or skill associations. `/workflow global` opens the same selector using global/default values without project overrides and omits the restore action. The title is `Workflow <scope>: <display-path>`, without a dash. Display the home directory itself as `~` and descendants as `~/…`, using the runtime home directory and a path-separator boundary; leave other paths unchanged, including similarly prefixed sibling directories. The actual destination path remains absolute and unchanged.
5. Save submits only changed `enabled` fields (or staged removals). The controller locks the destination, rereads/validates it, rejects conflicting changes to edited fields since the popup opened, merges unrelated changes, and writes atomically. No-op Save writes nothing. It preserves prompt/skill associations and untouched inherited fields. Success closes the popup and reports the persisted scope plus any reload/context warning; write failures report the error without claiming a save. JSON edits manage resource associations initially.
6. Status displays the project configuration path, each step's on/off state, prompt and skill paths, and configured/last-submitted skill paths. Apply the same home-directory abbreviation as the selector to these paths. Remove all enablement and prompt/skill source annotations; retain `none`, trust warnings, pending-discovery `/reload` guidance, and error diagnostics. Omit `Workflow skill selection submitted; native Pi diagnostics determine which skills loaded.` and the trailing `Prompts refresh on the next run. Previously read instructions remain in context; start a fresh session for a clean reset.` advisory from status only; save notifications remain unchanged. Status compares current desired skill paths with the runtime's last-discovered selection. A changed selection requires `/reload`; no reload is performed automatically. Prompts update on the next run, but previously advertised/read skills may remain until reload or in conversation history afterward. These limitations remain documented and in save notifications, not repeated in status.

On invalid configuration or unreadable enabled resources, report the exact path and do not silently fall back to defaults or last-good instructions. Discovery contributes no workflow skills on failure. Before-agent failures replace the workflow section with an explicit unavailability diagnostic, not partial workflow instructions; Pi may continue the run. Commands reject invalid writes. This is instruction management, not an execution barrier.

## Contracts & API changes
- Selector → native UI: title changes from `Workflow — <scope>: <absolute-path>` to `Workflow <scope>: <display-path>`; the project option changes from `Restore inherited enablement` to `Restore`. Selection matching uses the new label. Status → user: abbreviate displayed home paths and remove `(enabled: <source>)` and `(from <source>)` suffixes, retaining the actual prompt/skill paths. Omit routine successful-discovery and prompt/context advisory text from status, while keeping actionable pending-discovery guidance and errors. No JSON, command, SDK signature, or write-path changes.

| Provider → consumer | Current → proposed contract | Compatibility |
|---|---|---|
| Shipped/global/project JSON → resolver | TypeScript defaults → shipped JSON with complete `enabled`, `prompt`, `skills` entries for the four known steps; global/project fields remain optional | Same unversioned format; validate complete shipped defaults and partial overrides. Missing/malformed template is an explicit error, never a hidden TypeScript fallback |
| Step configuration → resolver | No bundle → optional `enabled` boolean, `prompt` path or null, `skills` array of `SKILL.md` paths | Omitted fields inherit; false disables, null removes a prompt, `[]` removes skills; arrays replace, never concatenate |
| Extension → Pi discovery | No workflow contribution → deduplicated absolute `skillPaths` | Additive native discovery; disabling cannot suppress copies registered independently elsewhere |
| Extension → Pi prompt builder | No workflow section → replaceable `sections.workflow` string | Other sections/tools/skills untouched; no raw system-prompt fallback |
| `/workflow` → user | No command → native selection popup; `global` selects global scope; `status` and `preview` provide inspection | `ctx.ui.select` supports TUI/RPC; guard with `ctx.hasUI` and report unavailable interactive editing without writes. Headless injection/discovery remain functional |

- Shipped `workflow/workflow.default.json` explicitly enables all four steps, sets their `workflow/prompts/<step>.md` paths, and lists `workflow/skills/mockup-first/SKILL.md`, `workflow/skills/roles/analyst/SKILL.md`, and `workflow/skills/roles/design-writing/SKILL.md` for mock, plan, and design; commit has `skills: []`. All resource associations and enabled defaults are data, not TypeScript expressions. The fixed step identifiers/composition order remain code-level UI contracts. Provenance identifies the actual shipped file for inherited values.
- Back up the user's current global `workflow.json`, then fill only omitted fields from the shipped template. Preserve explicit false/null/empty lists, custom paths, and unrelated JSON fields. No skill/prompt moves or startup writes are needed. The completed personal file is directly inspectable/editable rather than hiding associations in code.
- Project paths live under `<cwd>/.pi/`; its optional content convention is `workflow/prompts/` and `workflow/skills/`. Absolute paths are accepted; relative paths are resolved once at their source, so inheriting a global path never rebases it to the project. No environment/shell interpolation.
- Status shows resolved resource paths, configured versus last-discovered skill selections, and diagnostics, without field-level provenance annotations. Provenance remains available internally; this intentionally refines the original inspection requirement. Preview prints the exact proposed workflow-section content, not all Pi instructions or lazy skill bodies. Invalid known fields are errors; unrelated JSON properties are preserved by writes.
- Writes use an exclusive adjacent lock directory, a same-directory temporary file and atomic rename; always release owned locks. Recheck the source bytes before replacing to detect intervening manual edits. Contention or stale locks produce actionable errors; never steal a lock automatically. Project reads and writes are refused when untrusted; global scope remains usable.

## Decisions & Trade-offs
- Share a small presentation-only path helper between selector and status, using Node's built-in home-directory support without new dependencies. Do not truncate other path segments or rewrite diagnostic text, save notifications, stored paths, or discovery inputs. Existing native selection is retained; copy-only changes do not require a UI mockup.

- Use native discovery rather than injecting skill bodies or building a skill loader. The shipped [dynamic-resources example](../../../git/pi-chat/node_modules/@earendil-works/pi-coding-agent/examples/extensions/dynamic-resources/index.ts) demonstrates `skillPaths`. Inspected loader code rebuilds base resources on reload before adding extension paths, allowing previously contributed skills to disappear. Deduplicate canonical paths shared by enabled steps; native name-collision diagnostics remain visible.
- Managed skills live outside scanned directories. Move whole directories/subtrees to preserve assets and links; repair links crossing into the still-discovered developer skill. Remove unconditional plan/design gates from that skill and workflow mandates from memory/client guidance only with an approved, backed-up source checklist. Do not create symlinks or duplicate skills in scanned locations. Disabling is not a filesystem access restriction or a ban on explicit user requests.
- Target structured-prompt-capable Pi, with compatibility acceptance against the inspected SDK 1.0.2 and installed CLI 1.4.0. The repository's [SDK dependency](../../package.json) is 0.85.1: discovery/trust APIs exist, but structured `sections` do not. Use a narrow local structural capability adapter so existing extensions need no repository-wide dependency upgrade; report unsupported runtime clearly instead of replacing the full prompt. Another extension forcing an opaque full prompt can supersede structured sections and is outside this extension's control.
- Use a loop around native `ctx.ui.select`, as already used for checkmarked choices in [agent-defaults](../../agent-defaults/index.ts), rather than a custom multiselect renderer. Enter toggles one row and reopens the dialog; Save explicitly persists the batch. This avoids terminal-only UI and works with RPC clients' existing selection dialogs. Manual on/off commands are omitted. Association editing stays in JSON/Markdown; no interactive prompt editor, model-callable toggle tool, approval tracker, automatic commits, or automatic reload.
